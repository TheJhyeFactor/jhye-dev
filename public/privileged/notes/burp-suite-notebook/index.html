Playing Around With Burp Suite

A short note on using a repeater to turn a request into a controlled experiment.

A fictional note from a deliberately vulnerable local application. The useful part of a request repeater is not sending lots of requests. It’s holding most of a request still while changing one thing.

Give the experiment a question

Start with a request that works. Save that baseline. Then ask a specific question: does the server reject an absent field, ignore an extra field, or enforce the expected content type?

Change one input, send once, and inspect the full response. Status, headers, and body all matter. A response that looks different can still mean the same thing, and a response with the same status can expose different data.
