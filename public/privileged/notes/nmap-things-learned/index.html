A Few Things I Learned About Nmap

Why I keep the scope small, save the output, and read the reason behind a port state.

Written by Jhye

A quick fictional field note from a local test setup: scan output becomes much more useful when I can explain how it was produced.

Keep the first pass small

For a service running on my own machine, I can start with a few expected ports rather than every possible port.

The target is explicitly localhost. The TCP connect method uses normal operating-system connections. --reason includes why Nmap assigned a state, and -n avoids reverse DNS lookups.

Save the context

The command, timestamp, target, and output belong together. A result without scope is hard to compare later.

An open port does not prove a particular product is present. A service name inferred from a common port is a hint. Identification needs separate evidence.

↳ The bit worth remembering

The output is an observation from one place at one time. A different network path or host state can produce a different result.
